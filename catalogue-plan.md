Intake questionnaire is taken by all staff members logging in for the first time - this will be a list of our shop genre names, user can select unfamiliar, somewhat familiar or familiar about them and results about which ones they are familiar with are recorded

Admin/Orderer is assigned to ordering duty. 
All Admins or approved orderers are cycled through unless they are flagged as unavailable/on holiday from Roster
Ability to choose yourself for one of the upcoming weeks (fortnightly periods as default to start with)

->

Customer orders accumulate up to a chosen $ amount, default is $200 to start with. 

->

Admin/Orderer on ordering duty receives notification is the specified amount is hit
If staff items are being chosen, factor in an amount of time to give them to choose, order may overlap and be handed on to the next person on ordering duty

Admin/Orderer can manually trigger starting an order from the 'order details' screen

Point of Sale system can export a report which we. can import to gather information about which genre sections have dwindled in size

Suggestions of who to add to the order dependent on dwindling genres and their expertise level

Admin/Orderer can add other users to order to help choose

->

ORDER STARTED - percentage of 'classic bangers' vs customer orders (immutable) and leftover for risky picks is decided upon (slider possibly helpful here)

not every order will have customer orders in it but most will

->

Everyone involved in the order is notified of cutoff date for ordering and can opt out at this stage

->

$ amount difference between customer orders + necessary 'bangers' that we have flagged as such and the $ limit (default is $500 to start with) split up among everyone involved in the order

If the amount per person is less than the average price of one LP, some users are dropped and given higher priority for the next order (can't be dropped from next order)

->

2 days before (dependent on weekends/availability of admin) order due date, admin is notified of staff who haven't chosen yet, they can opt to chase them up or to drop them from the order and choose something themselves/add a classic banger

-> 

When chase up/selection/cutoff is finalised, remaining $ amount is displayed

Admin can choose to fill this themselves or return remaining amount to the kitty

Admin finalises order

System exports a .txt or .xlsx file to be pasted into an email or attached

Admin is given ETA for order arrival (calculated from data from previous orders that I need to procure from Nick's brain)

->

Order is received or notification is given to chase up if ETA has elapsed

If order received on/before ETA, admin ticks 'received'

Items entered into POS system, customer order items added to holds using information recorded when the customer orders
